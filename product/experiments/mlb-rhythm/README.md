# 独行侠：这一球，怎么进的？

分支 `experiment/mlb-narrative-rhythm`，独立试验入口。最终只保留弗拉格的独行侠进攻版本。火箭练习得到的字幕时机、减少重复停帧经验已经用于这一版。

## 故事顺序与画面

1. **先吸引，2.5 秒**：从原片 15.4 秒直接进入突破、起跳、挑篮命中，保留比赛原声。问题只有“这一球，怎么进的？”。
2. **回看解答，4.8 秒**：同一动作 0.5× 慢放，字幕在起跳画面出现时才提到举臂防守。交互画面用“突破—起跳—终结”提示引导目光；没有模拟球员追踪或补造动作。
3. **读懂机会，4 秒**：停在 16.5 秒的出手动作，展示官方 xFG 51.0%。给读者留时间，不连续堆多个指标。
4. **落回结果，4.1 秒**：恢复原速回看到命中后。短句说明命中结果与出手机会不同，让故事结束在比赛画面。

成片约 15.4 秒，xFG 在约 7.3 秒首次出现。黑橙风格延续原产品；1280×900 视频中，原画面完整缩放为 1280×720，字幕放在画面外，避免遮挡球员与篮球。完整 21.55 秒原片可从独立入口回看，短故事版不声称保留原片完整时间线。当前成片没有生成配音；节奏通过原声、慢放、停帧与字幕实现。

## 数据来源

读取 `product/data/stories.json` 已核对的 game `0022500701` / event `666` / player `1642843`；xFG `0.51`，实际突破挑篮命中。服务端和导出前核对原片 SHA-256；导出核对 verified 状态和指标一致性。动作描述依据视频，未把这一球写成扣篮、未命名无法证实的过人动作或战术因果。

## 复现

Python 3.11+，服务无额外 Python 依赖。将主办方原视频恢复到 `data/reference/train_video/train_video/训练_弗拉格2月1日.mp4`（也支持 `flagg.mp4`）。

```sh
python product/experiments/mlb-rhythm/serve.py --port 4180
python product/experiments/mlb-rhythm/render.py --sample flagg --ffmpeg /path/to/ffmpeg --font /path/to/chinese-font.ttf
```

入口 `http://127.0.0.1:4180/`，只提供独行侠；完整原片支持 HTTP Range。输出 `product/build/mlb-rhythm/flagg/enhanced.mp4` 和 `evidence.json`（来源时间映射、倍率、官方事件和输入/输出哈希）。媒体、字库和 build 不进入 Git。

## 验证与后续

核验开头源时刻、慢放停止、数据延迟揭示、原速收尾、重看隐藏指标、原片 Range 与移动端布局；本轮导出完整解码通过；Edge 浏览器实测播放至结尾，实际时长 15.421333 秒，1280×900。已检查数据揭示画面，字幕没有遮挡比赛原画面。浏览器交互和确定性剪辑不代表新 Agent 推理。本试验未调用 AWS、未改正式产品入口。借鉴 MLB 的“具体动作—情境数据—动作含义”方式，未使用棒球模型。

15 秒是本轮剪辑选择，是否舒适仍需真实新人观看反馈；下一轮应观察是否读完字幕、是否愿意重看、能否复述这次动作，不用虚构的观看率证明吸引力。
