# 俯视战术示意回放

桌面本地入口：http://127.0.0.1:4173/product/court-lab/。在仓库根目录运行 `python3 product/scripts/serve.py`，弗拉格观看页也有“换个角度，看这一回合”入口。没有 AWS、训练或 GPU 依赖；前端复用已有暖纸、深墨、篮球橙与像素字体。

## 当前实现

原片与 NBA 94 × 50 英尺球场并排。支持同步暂停、慢放、原片拖动、分析片段回放、半场/全场、两队筛选、匿名编号聚焦和一秒尾迹。两侧由同一个视频时钟驱动；默认停在分析窗口起点，分析回放到终点自动暂停。窗口之外清空点位。

`flagg.json` 为编辑示意版，`presentation: "schematic"`：从真实关键帧编辑大致地面点，投影后在不超过 0.6 秒、同镜头、两端可见的锚点之间插值。点间运动明确称“示意插值”，尾迹为虚线。遮挡点为空、没有外推，也没有补齐十人。编号只作画面对应，不代表自动识别 NBA 球员姓名。

用户明确此次优先快速低精度展示。因此只实现一个弗拉格短回合的空间回放，没有逐帧准确度指标、任意新视频处理、自动身份识别、球追踪、跑动速度/距离或战术因果结论。没有更改官方 xFG 与事件数据，也没有将俯视图烧录进已有完整成片。

## 文件与复现

- `index.html` / `lab.css` / `lab.js`：界面、唯一视频时钟、筛选和本地导入。
- `viewer.js`：数据校验、按时间采样、插值、断轨及球场坐标映射；通常省略 presentation 的数据最大连续插值间隔为 0.15 秒。
- `flagg-annotations.json` / `generate_schematic.py`：编辑像素点、真实 PTS、各帧标定与示意数据的可复现生成器。生成不调用模型或网络。
- `flow-flagg.json` / `generate.py`：早期衣物/地面光流实验，语义错误已拒收，不是默认展示来源。失败候选保留在[诊断](../evidence/court-lab-diagnostic-20261009.json)。
- `detector/`：官方 YOLO11n 的独立三帧检测验证与版本锁定，未接入产品；见[检测实测](../evidence/court-detector-20261009.json)。
- [技术调研与规则边界](../../docs/俯视图技术调研与实现边界-20261009.md)：现成篮球方案、模型许可、实际素材问题与范围核准状态。

在恢复已存档原片后，可重建编辑示意数据：

```sh
python3 product/court-lab/generate_schematic.py
node --test product/tests/test_court_viewer.js
```

编辑示意生成器只使用 Python 标准库，读取已保存标注与变换矩阵，并核对原片哈希；播放已保存 JSON 不需要 Python 库。另行重提取视频帧或复跑旧光流需要 OpenCV 与 NumPy。原片 SHA-256 与现有弗拉格来源一致。原视频不进入 Git，可从项目独立媒体存档恢复；派生关键帧和诊断图在 ignored 的 `product/build/court-lab/`，可重建。

导入 JSON 只在浏览器本地读取，不发送给后端。当前只接受绑定弗拉格源哈希的 `court-lab-v1`，不是官方评测协议。服务器仅暴露五个指定页面/数据文件，不开放生成器、检测权重或任意仓库文件。云端发布脚本没有包含此目录。

## 展示方式

点击“播放分析片段”看两侧同步；切半速观察移动；点击橙色编号聚焦深色队的一人，再切全场看空间分布。解释为：“同一回合，原片看对抗，俯视示意看站位。”来源说明保留在页面与文件中，准确性与编辑性质不依赖评委是否逐帧核对。

本轮只保存本地源码、测试和存档，未推送、未部署。正式入口范围、新素材与评测接口仍按主办方最新要求适配。
