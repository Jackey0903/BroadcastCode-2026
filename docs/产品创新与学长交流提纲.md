# 产品创新与学长交流提纲

更新：2026-10-06。用户明确纠正研究方向：本次是面向评委展示的黑客松产品原型，交流重点是可以借鉴的产品创意、篮球洞察与展示方式。此前模型、代码和权重核查保留为技术备选，不作为当前交流的主线。以下是推荐候选，尚未实现，也不代表已证明首创或用户已定稿。

## 1. 创新应该让评委体验到什么

推荐产品承诺：**同一个回合，第二遍看懂一件刚才漏掉的事。**

产品创新的价值体现为：观众做一次简单操作，就获得一个新的、正确的理解；这种差异能直接在比赛画面里看见。既满足准确数据和自动成片的基本交付，又让评委记住一个招牌体验。

我们不需要等待科研模型创新。可以将已有能力重新组合为观看流程、选择关注对象、按需揭示证据和自动导演的增强回放。成果应如实说明研究启发与自己的产品设计；目前没有进行广泛竞品查重，不能称世界首创。

## 2. 六个值得讨论的产品创新候选

|候选|评委操作与看到的变化|新理解|最小原型与推荐|
|---|---|---|---|
|**这一拍，你第一眼看谁？**|关键时刻停帧，点一个球员，随后观看对应的聚焦回放|发现持球者之外的动作，或重新理解攻防动作先后|一个关键帧、两三个关注对象、短回放；主创新候选|
|**一拍之前**|看完终结，点击回到最值得解释的出手前时刻，逐步揭示动作与回应|精彩之处可能发生在进球之前|一个自动选出的关键章节，少量定格与强调；主体验的叙事结构|
|**同一球，换个人看**|切换进攻者与防守者焦点，原视频和时刻不变|同一次进球里，能同时观察进攻处理与防守限制|只做两个差异明显的焦点，不生成三套雷同长文；辅助候选|
|**投进以后，难度没有消失**|终结时查看真实结果与对应官方出手指标，再回看干扰|实际命中与出手条件提供不同信息|一项准确事件指标加局部画面；依赖官方数据，不能据此宣称唯一最优选择|
|**点一句解释，让视频作证**|点击“防守人先起跳”等解释，立即回到支持片段，逐步突出对象|观众可以亲自检查关键结论|解释关联时间窗口；贯穿作品的可信交互|
|**这一球，紧的是哪只钟？**|按需强调比赛时钟和进攻时钟，解释当前约束|区分末秒出手与整场决胜时刻|读取实际时钟，配一条短解释；小成本内容亮点，按素材使用|

“第一眼看谁”记录的是观众主动选择的关注对象，不测量眼动，也不声称知道观众真实视线。选择改变观看焦点；不设牵强的唯一正确答案、不假装预测比赛结果。没有可靠无球贡献时，可以聚焦防守或出手节奏。

## 3. 推荐组合：一个主创新、两项支持

**主创新：互动式的“一拍之前”。**

```text
先看原片 → 回到关键一拍 → 选择关注谁 → 聚焦回放 → 发现一个新细节
                                                    ↓
                                           点解释，回看依据
```

它将“停帧选择”与“换个人看”合为一次体验。完整增强 MP4 保持默认可直接观看；观众愿意探索时，再进入短回放和焦点选择。只在一个最有解释价值的时刻安排互动，避免全程答题。

**支持一：解释可点回画面。** 用户不离开观赛页面，直接看到该结论依赖的几秒录像。官方数据按需展开，默认不显示技术日志。

**支持二：数据在关键时刻揭示。** 数字与出手动作关联，在它能回答当前问题时出现。避免让图表长期占据画面；实际结果与官方指标分开解释。

不把全部候选做成平行功能页。先让评委完成一次连贯体验，再用必要的功能说明展示自动处理能力。两个焦点必须有不同内容价值，不能只换文案或颜色。

## 4. 两段样片如何形成具体亮点

### 阿门片：出手之前，谁先起跳？

已有抽帧显示约 17.5 秒时，深衣 00 号已起跳，白衣 1 号仍持球；随后可见 1 号出手。它适合讨论“观众看球时容易漏掉的动作先后”。正式制作还需连续回看，核准具体帧。

拟定 15 秒演示：前 4 秒播放相关动作；接着定格并让用户选择关注进攻者或防守者；随后慢放揭示动作顺序；最后点击一句解释回到证据。可以讨论出手节奏，但不凭几张截图确定“成功骗跳”或虚构替代选择的命中率。

片中第三节比赛时间与临近结束的进攻时钟，也能支持一个清楚的问题：“这一球紧的是哪只钟？”

### 弗拉格片：球进了，防守做到了哪一步？

已有抽帧支持突破后的受干扰终结。可以先看进攻者的处理，再聚焦迎向出手的防守人。用户第二遍发现可见的防守压力；取得匹配的官方 xFG 后，再把过程与指标关联。不能仅凭进球说防守失败，也不能把低 xFG 自动解释成错误选择。

21 号的无球作用可以作为交流候选；是否为有效掩护、顺下或牵制，需要连续动作确认，不能预先写成确定剧情。详见[样片核查](research/公开训练样片核查.md)。

## 5. 从学长工作中借鉴的是产品思路

学长的[主页](https://jyrao.github.io/)介绍了 MatchMate 的观赛问答、个性化解说与多种观看形式；TennisVAR 将关键动作、支持事件和解释关联起来；MatchTime 关注画面与解说的时间对齐。它们提供讨论入口，不代表作者已经实现了上文的产品候选。

|研究或产品启发|我们提出的转化|应向学长交流的判断|
|---|---|---|
|MatchMate 的主动参与和观赛体验|让用户选择当前想关注的人或问题，获得短回放|用户最愿意进行哪一次操作？哪些参与方式会打断看球？|
|TennisVAR 的关键动作与支持证据|点击解释就重看最有说服力的动作|哪一个瞬间最值得揭示？怎样避免把动作先后误写成因果？|
|BasketEvent 的人物与事件关联|同一个回合从不同人物焦点再看一遍|哪些无球动作、防守回应最容易被普通观众漏看？|
|MatchTime 的时序对齐|让解释在观众看得见对应动作时出现|什么时刻值得暂停、慢放或保持原速？|

代码、权重等技术资料仍可在选定体验后按需询问；当前优先获取的是他们对**观众注意力、篮球内容价值和展示节奏**的判断。详细技术备选见[原研究核查](上交AI4Sports研究借鉴与交流建议.md)。

## 6. 一次交流最值得问的五个问题

1. 看这两个回合，哪个细节能让普通球迷在十秒内产生“原来如此”？我们的哪一句解释应当删除？
2. 你们研究中有哪些已经能分析出来、但还没有被很好呈现给普通观众的信息？如果只做一个交互，会选什么？
3. 在体育产品中，直接看解释、选择关注对象、回答一个小问题，哪种更有参与感？有没有真实用户观察，而不是仅凭直觉？
4. 哪些体育可视化看起来很炫，却容易误导或增加理解负担？尤其怎样呈现无球贡献、防守压力与出手质量？
5. 如果只有五分钟展示给 NBA 和 AWS 评委，我们应该把哪一个用户动作做成招牌？怎样验证观众看后确实多理解了一件事？

建议带去的材料只有三项：两段公开原片；一份 15 秒体验分镜；两个最想请他判断的问题。先看原片和体验，再按讨论需要解释技术路线。

用户可以自行发送的交流开场草稿：

> 学长好，我准备参加 NBA × AWS 的 BroadcastCode 黑客松，主要想做一个面向评委展示的篮球观赛产品原型。我更想请教产品创意：你们做体育 AI 和 MatchMate 时，有哪些分析能力或篮球细节，如果变成可视化和交互，会让普通观众觉得“原来还能这样看球”？我们想到一个方向：关键时刻停帧，让观众选关注谁，再用短回放揭示刚才漏掉的动作。想拿两段公开样片和你交流一下，看看这个体验是否有价值，还有没有更好的创新切入点。

## 7. 快速原型的检验方式

找未参与设计的人先看原片，再体验增强回放。请他指出看后新理解的一件事，并在原片中找到依据；同时记录是否能独立完成选择与回看。答案需要正确且与实际画面有关，不能只统计“觉得很酷”。

时间、理解率与吸引力都还没有测量。主创新是否最终采用，要根据样片内容、体验样稿与实际测试判断。自动处理、完整烧录成片、真实官方数据、AgentCore/CDK/CloudFront 和赛事区域约束仍是开发底座。
