## 一分钟以内的视频怎样突出RL

让观众看见“模型找到哪些证据、证据帮助解释什么”。短标签和数据卡随原视频呈现，不另加长训练介绍，不遮住球、持球人和比赛时钟。

|呈现位置|建议内容|实施条件|
|---|---|---|
|开头非关键动作处，约3秒|`RL 数据球探`，副标`AWS SageMaker · 3B`|本次成片使用的模型结果已通过来源核验；纯训练介绍须明确写“模型训练已完成”|
|回合结束后的复盘，约4秒|两张短卡：`全场 34分`、`全场 eFG 54.0%`；共同小字`赛后统计 · eFG由官方计数计算`|从本次模型返回的对应evidence读取，不把全场数值写成出手时实时数据|
|随后复盘，约5秒，深度数据作为重点|`无球外线引力 6.217`；小字`2025–26赛季 · 深度赛场`|这是弗拉格已核验示例，不加百分号或自造排名；只作球员背景，不推断本回合引力数值、轨迹或因果|
|片尾或网页证据抽屉|`画面理解 → RL选证 → 来源核验 → 数据解读`，另列三层来源|完整流程的措辞只用于真实接入后的成片；来源详情可展开，视频保留简短范围标签|

以上是相对动作位置的呈现建议，不是未经看片确定的精确时间码；复用已有慢放/复盘段，由链路Codex与队友按素材压缩，总时长仍不足一分钟。官方事件xFG `51.0%`沿用原出手时机与来源，不标成RL预测。Gravity、Leverage、Shot Difficulty按当前回合的解读重点选一种重点展示，不为堆指标同时塞满画面。

弗拉格示例来自已通过的模型请求：player `1642843` / game `0022500701` / event `666`；34分、eFG 54.0%、引力6.217分别对应证据ID `e10e1bdacb4be`、`e09ba1fae361c`及同一响应中的Gravity记录。完整记录见[主例真实调用](../product/rl/results/evidence-v1/service-connection-recovery-20261010.json)。18:00正式素材须重新核对身份、事件与来源，不预套这些数字。

## 完整说明与结果边界

已完成：我们在AWS SageMaker GPU上训练了一个3B数据球探，让它通过工具选择NBA官方基础数据、由官方计数计算的高阶效率，以及NBA/AWS深度赛场的引力、影响力和出手质量数据。球探输出有来源的证据，程序核验指标和适用范围。待后端接入：现有视觉与叙事模型结合画面解释，使用这些证据生成带数据的完整视频。
