### 两个模型结合后，具体得到什么

现有视觉大模型（当前产品已验证Claude）输出可观察动作、真实画面时间与证据；拟训练3B输出一个简短的**数据证据包**：

1. 当前进攻对应的比赛、事件和已核实球员。
2. 回答当前问题所需的基础、高阶、深度数据及真实来源。
3. 可以成立的比较或背景关系，以及缺失、粒度与时间限制。
4. 值得讲述的数据角度与关联画面候选；画面位置来自视觉证据，不能由文本3B编造。

程序校验后，把证据包交回视觉/叙事模型，生成按画面时间组织的短解读；Worker将批准的数字与字幕真正烧录进MP4。两个模型采用明确分工和工具调用连接，不计划今天合并权重或训练新的视觉骨干。

期望改善是：事件不串、数据用得对、解释不只复述进球、重点不被无关指标淹没。提升幅度需与同题无训练版本比较，不能预先承诺。当前v4还只能提供同类出手估计；三层证据包是下一轮拟训练能力，不冒充当前产物。

|---|---|---|

给队友的视觉目标：每一时刻聚焦一个动作，最多两项数字，来源和“赛季背景”短标签清楚；呈现风格沿用其前端方案。本会话不改前端。

## 1. 先明确要训练什么

目标改为：**面对一个视频回合和观众问题，Agent 找到准确事件，选择相关的基础数据、高阶背景和深度赛场证据，解释这一拍值得关注的地方，并给出可核对的依据。**

三类数据不必每次全部展示，但训练必须覆盖需要联合它们才能回答好的问题。后端保留完整证据，成片优先展示最有用的 1–2 个数字与一句解释；其余放在可展开的依据中。不能把三张统计卡并排就称为联合理解。

当前 v4 的任务只是估计同类出手的常见 xFG 与区间，范围过窄。它可以保留为辅助研究，但不再作为下一阶段主目标。NBA/AWS 把深度赛场扩展到出手难度、防守压力、引力和影响力；我们应围绕这些信息设计观众问题，而非只复现一个命中质量数值。来源：[AWS NBA 合作说明](https://aws.amazon.com/sports/nba/)。

## 3. 三层数据如何真正结合

这里的三层是工程分工，部分统计在 NBA 网站分类中可能重叠。

|层次|优先数据|负责回答|如何连接下一层|
|---|---|---|---|
|基础：事实与产量|事件、节次、投篮类型、结果；完整官方得分、投篮/罚球次数、助攻、篮板、失误、分钟|谁在什么事件做了什么；贡献有多少|提供事件身份、统计分母和画面联接键|
|传统高阶：效率与角色|球员 eFG%、TS%、USG%、AST%；球队进攻/防守效率、Pace、篮板率、失误率|同样产量用了多少机会；球员承担什么角色；球队环境如何|为深度指标提供合理比较对象，而非另造“综合价值分”|
|深度赛场：机会与关注|事件 xFG；同口径赛季 Shot Difficulty / FG%+；持球与无球、内线与外线 Gravity；创造机会、篮板、防守等 Leverage 子项|机会本身质量如何；传统计数以外还能关注什么|与同一主体的基础/高阶背景形成解释，选择值得回看的画面|

**首批三类故事：**

1. **“这球进了，它的机会质量怎样？”** 联合动作/结果、同范围投篮效率与投篮结构、该事件 xFG。可进一步对照球员同类型机会质量背景；展示官方 xFG 时是检索事实，不能算模型预测成绩。
2. **“没直接得分的人，有什么值得看？”** 已验证的传球/助攻或画面观察，联合 AST% / 使用角色与无球引力、创造机会 Leverage。模型应选择有证据的人物与片段；赛季背景不能证明这次具体防守移动由某个人造成。
3. **“这次篮板或防守为什么值得讲？”** 官方该次篮板/失误等事件，联合球队篮板/失误背景及球员对应 Leverage 子项。没有正式事件级 Leverage 时，保持赛季背景表达，不输出本回合胜率增加多少。

使用顺序由问题决定。例如“这球官方 xFG 是多少”只需要事件工具；“为什么值得关注无球球员”才需要额外角色与引力背景。不能通过奖励强迫每题调用三个工具。

## 5. 数据接入与缺口处理

**先建两队可追溯数据包，再训练。** 主键为比赛、事件、球员、球队；每个指标单独记录主体、单位、统计周期、事件/单场/赛季粒度、抓取时间、统计截止、来源地址与内容哈希。球队归属必须区分事件当日与当前赛季快照，不能靠名字模糊联接。

优先补齐：两样片对应比赛的完整 box score → 两队球员 eFG/TS 与角色字段 → 两队效率背景。来源优先主办方正式文件和实际可访问 NBA 官方数值接口。某个字段缺失不阻止使用已经取得的其他字段。

如果官方高阶接口暂不可取，可从**同一范围的完整官方计数**计算 eFG、TS，并明确标注“由官方基础数据计算”。只允许有完整分母、版本固定的白名单公式；不能从当前8人局部出手、场均值的简单平均或残缺罚球字段伪算。USG、球队效率和Pace需要额外回合/在场等口径，不能用一个粗略替代值贴上官方标签。公式口径参考 [NBA统计词典](https://www.nba.com/stats/help/glossary)。

深度指标接入优先级：

|优先级|内容|进入联合工具的方式|
|---|---|---|
|P0|事件 xFG、Shot Difficulty 的同类型均值与FG%+|事件事实与赛季机会/执行背景分开返回|
|P0|持球/无球 × 内线/外线 Gravity|按用户关注点选择对应子项；带赛季范围，缺项不补零|
|P0|创造机会、投篮、篮板、防守等 Leverage 子项|用于选择解释角度和人物，数字按原来源显示|
|P1|逐次防守压力/距离、事件级Leverage|只有实际取得并确定单位/粒度才启用；当前 `def` 返回空，不进入训练标签|

输出区分“官方事实”“画面观察”“程序计算”“模型解释”。当前全赛季快照可用于赛后背景解读；若题目问截至赛前状态，则需要真实历史截止，不能把抓取时间当统计截止。两队内部比较只称两队已覆盖球员的比较，不称联盟排名。

## 6. 模型、程序和后端分别做什么

**现有视觉 Agent 读画面 → 3B或固定策略选择数据工具、组装证据关系 → 程序验证身份与数字 → Claude表达 → Worker按批准的证据烧录。** 这是一条待实现的职责划分，不新增无必要服务。

- **3B 的学习目标**：选对工具、正确联接主体与时间、补足必要证据、发现缺失、输出合法的关系。当前 Qwen2.5-3B 是文本模型，不称视觉模型。
- **程序的职责**：查询、计算、源数据校验、单位转换和最终显示值；不能把这些交给模型凭记忆生成。
- **Claude 的职责**：延续现有图像观察和叙事，用已经通过校验的证据解释画面；不添加未经验证的新数字。
- **后端接入点**：另一个 Codex 扩展官方数据工具及统一指标契约，再交给 Worker。现有 `canonical_metrics` 仅支持绑定事件的 xFG，不能把负引力或Leverage硬塞进概率字段。
- **前端交付**：给队友统一的数字、短标签、范围、来源、回看建议，由其决定视觉。训练会话不修改前端。

结构化输出使用短证据ID引用事实，证据仓库存完整来源信息；不要让3B在每次回答里重复长URL与哈希。关系先限定为可核验类型：产量—效率背景、机会—命中差值、角色—防守关注背景、基础贡献—影响力背景。任意开放式篮球因果推理不靠格式检查判真。

## 7. 训练策略与奖励

先跑通两段视频的联合证据解读，再考虑训练。建议从已有410题抽取合格的检索/缺失底座，新增真实跨表任务；不能把410题改名就算完成联合数据集。

|建议任务比例|训练内容|
|---|---|
|15%|事件对齐、基础事实和身份纠错|
|20%|基础产量与传统高阶效率/角色的关联|
|35%|两层或三层跨表关系解读，重点覆盖引力/Leverage与机会质量|
|20%|缺失、时间、单位、错球员与因果诱导反例|
|10%|保留xFG隐藏标签估计，独立报告其数值成绩|

深度指标还进入部分反例任务；数据集汇总须列出指标家族覆盖，确保Gravity、Leverage、ShotDifficulty都有真实任务，而不是把35%全部做成xFG换一种问法。这个比例是待试验设计，不是现有样本分布。

建议先用250–400条经程序核验的工具轨迹做小规模SFT，让模型学会协议和关联；再做**一条有时长上限的短GRPO**，不同时启动多版大实验。先比较原始3B和SFT，不能默认旧v4的单工具习惯适合新任务。输出预算另按联合协议长度测定，不能直接沿用旧任务160-token限制。

联合任务的初始奖励建议：

`R = 0.30×事实正确 + 0.25×真实证据 + 0.20×必要信息覆盖 + 0.15×关系正确 + 0.10×格式正确 − 0.002×实际工具调用数`

- 事实核对数值、单位、对象和周期；证据必须来自执行器记录的真实返回。
- 必要信息由题目标准决定。少答、全拒答、只给漂亮格式不能拿高分；无关指标堆砌也不加分。
- 错事件/球员、伪造来源、赛季数值冒充本回合、未来数据冒充赛前、无依据因果等硬错误，整题负奖，不能被其他正确数字抵消。
- 正确返回“缺失”只在来源确实缺失时得分；有数据却拒答仍失分。
- 不奖励调用工具数量、文案长度、说出“引力”等关键词；同样充分的证据允许不同合法调用顺序。
- xFG子任务仍用独立数值奖励，不把检索到官方答案记成预测成功。完整审查见[联合训练评审](research/三层数据联合训练评审-20261010.md)。

## 8. 怎样判断联合方案确实有效

先冻结约60个开发任务和约120个独立留出数据任务，数字是小实验预算建议。按整场/源事实组分割后再写问题，同一事件的改写不得跨集合；现有390次交手已用于开发，不能重新命名盲测。检索评测可以从工具查到留出球员官方行，考的是工具使用；隐藏标签预测则必须屏蔽目标及同场泄漏。

在同题、同模型、同调用预算下比较四种数据条件：**基础；基础+高阶；基础+深度；三层齐全**。再比较固定策略、原始3B/SFT、SFT+GRPO及Claude同工具基线。先筛任务价值，再对入围方案做完整比较，避免无必要地排列组合消耗。

主要指标：整题成功、关键事实/粒度错误、必要信息覆盖、正确缺失与错误拒答、工具次数、时延。格式有效率建议至少99%，关键错源/错事件必须修正；小样本通过不等于未来输入零错误。两段视频只验证两段成片，纯数据题不能累计成看视频成功数。自由文字抽查少量代表性例子，训练奖励不替代篮球内容复核。

联合数据的价值应体现为“基础版答不完整、联合版多给出了一条正确有用的关系”。若完整数据加进来没有改善，就检查任务和联接；若RL没有超过SFT/固定策略，则产品继续使用有效的联合工具链，训练结果照实保留。
