## 1. 完整视频入口：CloudFront → API → Worker

当前实现从 [Web API](../product/api/handler.py)接收任务，经 SQS 交给 [视频 Worker](../product/worker/handler.py)。Worker 下载原片、核对来源与时长，调用 AgentCore 获取计划，再用 FFmpeg 将章节、来源标签和可核准指标烧录进完整 MP4。AgentCore 的计划完成与视频成片完成是两个状态。

| 请求 | 用途与返回 |
| --- | --- |
| `GET /api/status` | 返回服务状态、登记素材列表、区域、Runtime ARN 和模式；登记配置缺失时返回 `503`。此接口成功不证明模型推理成功。 |
| `POST /api/jobs` | JSON `{"sample":"flagg","mode":"story"}`；成功返回 `202` 和 `{"jobId":"32位小写十六进制编号","status":"queued"}`。 |
| `GET /api/jobs/JOB_ID` | 读取同一个任务；返回 `status`、`stage` 及运行信息。任务不存在为 `404`，编号格式错误为 `400`。 |

`mode` 必须明确为 `story`；省略后默认进入旧 `readiness` 流程。公开任务使用共用运行次数预算，当前 CDK 设置为 30 次；不要把评委或队员的重复点击当成无成本检查。

CloudFront 的 Lambda IAM 源要求 POST 带 `x-amz-content-sha256`，值为**实际发送的原始 UTF-8 请求体字节**的 SHA-256 十六进制摘要。不能在计算摘要后修改 JSON 的空格、字段顺序或编码。[前端](../product/web/app.js)和 [run_sample.py](../product/scripts/run_sample.py)已实现；网页无需 AWS 密钥。

在仓库根目录复跑一个已有案例：

```sh
python3 product/scripts/run_sample.py --sample flagg --wait
```

这条命令会启动一次真实模型和渲染任务。脚本只发一次 POST，然后约每五秒查询原任务，最长查询约二十分钟；终态记录写到被 Git 忽略的 `product/build/client-jobs/JOB_ID.json`。要测试阿门，换为 `--sample amen`，不要为了看同一结果重新提交。

若 POST 超时或响应丢失，结果属于未确认，不能据此推断服务未接收。已经得到编号时只读查询：

```sh
curl -fsS 'https://deky02484tknr.cloudfront.net/api/jobs/JOB_ID'
```

常见阶段为 `queued → loading_inputs → analyzing → rendering → publishing → completed`，处理中 `status` 为 `processing`；失败终态为 `failed`，含真实错误字段。轮询超时也不表示任务失败，继续查询原编号。预算耗尽返回 `429`；不要通过重复创建任务绕过预算。

## 2. 产物与独立核验

成功任务在当前桶生成：

```text
product/outputs/JOB_ID/enhanced.mp4
product/outputs/JOB_ID/analysis.json
```

任务完成记录提供当前 CloudFront 的 `videoUrl`、`analysisUrl`、`videoPath`、`outputSha256`、`outputDurationMs` 和 `preservesSourceTimeline`。分析 JSON 保存模型／Runtime／会话、真实工具调用 trace、用量、来源帧、官方记录、验证结果和输出视频 SHA-256。

现有成片画布为 `1280 × 900`，原画面位于 `{x:0,y:76,width:1280,height:720}`，文字和指标在原画面之外。Worker 检查完整时长、画布和原片音轨保留，不把页面临时叠加当成最终成片。

对现有两训练案例的已完成任务，可独立下载并核对：

```sh
python3 product/scripts/verify_run.py JOB_ID
```

[verify_run.py](../product/scripts/verify_run.py)不会启动新推理；它检查当前 Runtime、来源时间轴、SHA-256、H.264、画布、音轨及 HTTP Range `206`，并保存本地证据。该脚本目前按有音轨的两案例与固定模型、固定抽帧时刻核验；其他短片需要适配核验条件。它明确保留 `browserPlaybackVerified:false`、`burnedOverlayVisuallyVerified:false`，因此还必须播放全片、检查永久字幕与篮球内容。`--promote` 会修改展示选择，仅在内容复核后使用。

生成文字的时钟判断另有质量约束：当前没有时间对齐的进攻时钟证据，Agent提示与共享故事契约拒绝生成进攻时钟、读秒或时间紧迫结论（覆盖标题、概要和章节文字）。阿门正式首次任务因早段时钟措辞与实际19秒不符被内容拒收；该任务不用于最终展示，时钟防护已部署；本轮不追加重跑，观看区沿用标注historical的已验收阿门历史片。

历史增强片重新发布时，观看区及每故事的 `publication.historical` 明确标记历史来源；原 Runtime／trace 不能改成新账号执行。历史片的 HTTP 可播放与当前账号真实新任务验收须分别记录。

## 3. 直接 AgentCore 调用的边界

[Agent HTTP 入口](../product/agent/main.py)按 `mode` 分派；故事调用的内部请求包含：

```json
{
  "protocol_version": "team02-readiness-v1",
  "request_id": "formal-example-01",
  "mode": "story",
  "video": {"id":"formal-01","name":"source.mp4","s3_uri":"s3://CURRENT_BUCKET/samples/formal-01.mp4","duration_ms":10000,"sha256":"SOURCE_SHA256","width":1280,"height":720},
  "frames": [{"timestamp_ms":1000,"s3_uri":"s3://CURRENT_BUCKET/frames/formal-01/frame-00.jpg","format":"jpeg"}],
  "story": {"id":"formal-01","durationSeconds":10,"sourceVideoSha256":"SOURCE_SHA256","storyOptions":[{"id":"observed-play"}],"officialEvent":{"verified":false},"evidence":[]}
}
```

这里的数值只是字段示例，`SOURCE_SHA256` 必须替换为实测 64 位小写十六进制值；示例不是可提交的真实测量数据。实际请求必须来自测量与登记结果。[输入校验](../product/agent/readiness_agent.py)要求来源 URI 指向受控桶，宽高为整数，帧数为 1–6，时间戳唯一且处于原片范围；[故事校验](../product/agent/story_contract.py)核对同一视频、时长、SHA 和证据。

故事 Agent 会实际执行 `inspect_frames`、`read_official_event`，随后单独一轮执行 `validate_story`。其结果使用 `product-story-v1`，提供 `plan`、`trace`、指标与来源，并不执行完整视频烧录。**直接 AgentCore 返回 `status:completed` 只表示计划完成，不能当作完整视频评测入口或渲染成功。** 要取得增强 MP4，必须经过 Worker，并按第 2 节检查产物。

## 4. 新素材的本地登记

[register_case.py](../product/scripts/register_case.py)是离线登记器：不调用 AWS、不推理、不渲染，也不自动上传。它用本机 `ffprobe` 测量原片，用本机 `ffmpeg` 解码抽帧并通过 `showinfo` 记录实际原视频时间戳；不能用 Lambda 的 Linux 二进制替代 Mac 工具。请求时间和实际选中帧时间分别保存，不能把请求时刻冒充观测时刻。

| 项目 | 当前登记限制 |
| --- | --- |
| `sample` | 最长 60 字符；首字符为小写字母或数字，其余为小写字母、数字、`_`、`-`；不覆盖既有 ID。 |
| 原片 | 普通本地 `.mp4` 文件，不接受文件本身为符号链接；有 MP4 容器头，12 字节至 256 MiB。 |
| 视频 | 实测时长大于 0 且不超过 60 秒；宽高为 `[1,8192]` 内整数。60 秒是保守登记范围，不是处理吞吐保证。 |
| 帧 | 请求 1–6 个不同有限时刻，`0 ≤ t < duration`；实测 PTS 同样必须有效、不得早于请求，重复实测时间被拒绝。 |
| 图像 | 实际 JPEG，最大 `3,500,000` 字节；每张计算 SHA-256。 |
| 元数据 | 通过已有 Agent 输入与故事契约；与实测 ID、SHA、时长冲突则拒绝。未独立复核提供者的篮球结论。 |
| 输出目录 | 必须不存在；成功后才整体移入最终目录，不覆盖旧登记包。 |

没有确认的官方指标时，使用 `officialEvent:{"verified":false}` 并**省略 `shotMetric`**。不填猜测的 xFG、球员身份、事件编号或轨迹。确有官方指标时需要提供原值、`ratio/percent` 单位、出处和一致的 `gameId/eventId/playerId`；结构校验不替代真实性与篮球内容复核。

新增到现有登记表时，必须先取得**当前同一目标桶**的完整 `samples.json` 和 `stories.json` 快照，作为 `--manifest`、`--stories`。不能用旧账号 URI，不能把空 manifest 当成现有表：省略 `--manifest` 会以空表开始，后续发布这个表会丢失其他素材登记。脚本复制传入记录，不会自动读取云端或迁移所有历史 URI。

将真实提供的故事元数据、原片及上述快照准备在本地后：

```sh
python3 product/scripts/register_case.py \
  --sample formal-01 \
  --bucket CURRENT_BUCKET \
  --video product/build/formal-inputs/source.mp4 \
  --story product/build/formal-inputs/supplied-story.json \
  --manifest product/build/formal-inputs/current-samples.json \
  --stories product/build/formal-inputs/current-stories.json \
  --frame-time 0 --frame-time 3 --frame-time 7 \
  --output-dir product/build/registered-cases/formal-01
```

帧时刻必须按该原片真实时长选择；上面的三个时刻只是调用示例。最小故事元数据可包含 `storyOptions:[{"id":"observed-play","label":"画面解读"}]`、`officialEvent:{"verified":false}`、`evidence:[]`，由实际帧支撑模型观察；这不等于完整展示卡或官方内容验收。

成功登记包保存 `source.mp4`、实际 JPEG、`samples.json`、`stories.json`、`registration.json`、原始 `supplied-story.json` 和带哈希／字节数的 `publication-plan.json`。计划将素材与帧放在登记 JSON 之前，并指定同时更新：

```text
config/samples.json
product/config/samples.json
product/data/stories.json
product/registrations/登记ID.json
```

**新登记包仍是本地发布计划，没有自动写云执行器。** [publish.py](../product/scripts/publish.py)目前负责两个已验收训练案例，不能拿它直接发布任意新登记包。受控注册表API／Worker更新已部署；新增案例仍须按计划验证并上传同桶素材／登记文件，部署对应代码，再跑一次新 ID 的真实完整流程；第三案例的上线与验收不能由“登记成功”或两训练片成功代替。

## 5. 两训练案例的官方关联

| 登记 ID | 球员 | `gameId` | `PBP.actionNumber`／`gpShot.eventId` | xFG 原值及展示 |
| --- | --- | --- | --- | --- |
| `flagg` | Cooper Flagg／弗拉格 | `0022500701` | `666` | `0.51`，`ratio`，`51.0%` |
| `amen` | Amen Thompson／阿门 | `0022500491` | `396` | `0.445`，`ratio`，`44.5%` |

关联键为 **`gpShot.eventId = playByPlay.actions[].actionNumber`**，不是数组下标，也不能用别的名为 `eventId` 的 PBP 字段替代。编辑锚点与确定性匹配已交叉核对球员、节次、时钟、出手类型和命中；见 [事件关联](../product/data/event-bindings.json)、[故事来源](../product/data/stories.json)及[锚点](../product/data/video-anchors.json)。这是两个训练视频的已策展关联，不是对任何新视频的自动 OCR 或通用事件识别。

xFG 表示该次出手的预期命中率，不是球员赛季命中率或结果保证。官方提供的是出手瞬间点位，不能据此编造逐帧轨迹；本地俯视板继续作为编辑示意，不纳入正式自动追踪声明。

## 6. 拿到官方评测 schema 后的接入验收

先保留主办方原始请求／响应样例，确认视频和深度数据定位方式、字段类型与单位、调用入口、超时、产物路径及仓库重跑命令，再编写显式的外部协议适配器。现有本地登记器只能产生内部输入，不能自行定义官方字段。

离线至少覆盖真实样例、缺失字段、错误单位、跨桶 URI、来源 SHA／时长不一致、未知或未经确认指标、非法 ID 和缺失产物；未知官方指标应省略。线上再以正式素材单次创建任务，记录 AgentCore 真实调用、完整增强 MP4／analysis、哈希、音轨与时长，最后在 CloudFront 播放到末尾并检查数据准确性。

可先复跑登记器现有离线测试：

```sh
python3 -m unittest discover -s product/scripts -p 'test_register_case.py'
```

合成测试通过、登记包生成、两练习案例成功和正式评测通过是不同证据。本文件不宣称正式考试素材已验收，也不把内部协议包装成评分认证。
