## 一次改动的最短可靠流程

1. 明确改动解决的产品问题、评分项和验收依据，优先补真实链路／新输入／准确性，再改善展示。配置和数据契约集中管理，不复制旧账号常量。
2. 实现最小完整增量，针对风险加行为测试。静态文案或低影响视觉修改不堆机械测试；对新输入校验、失败恢复和账户迁移则必须覆盖关键边界。
3. 运行统一离线门禁；界面改动另外验证桌面浏览器，渲染改动另外验证完整视频，云端改动另外验证实际运行。成功记录写明版本、账号、输入、时间和范围。
4. 检查差异，整理源码、锁定文件、测试和说明，提交新 `origin/main` 并推送。推送和 GitHub CI 成功分别核对；失败时保留本地版本并修复，不称尝试为成功。
5. 在干净提交上执行[本地存档](源码保存与恢复.md)，服务器只保留部署副本。大视频和运行凭证不提交 Git。

## 统一离线门禁

在仓库根目录运行：

```sh
# 新电脑首次安装；使用仓库现有锁定文件。
npm ci --prefix product --ignore-scripts --no-audit --no-fund
# 默认也是完整档。
python3 product/scripts/check.py --full
# 快速反馈：源码、语法与基础设施；正式同步前仍运行完整档。
python3 product/scripts/check.py --quick
```

[检查入口](../product/scripts/check.py)检查可提交文件中的凭证风险、当前产品 Python／JavaScript 语法、所有既有行为测试，以及实际 CDK 应用合成后的账号、区域、AgentCore 角色、权限边界和 bootstrap 资产桶。发现失败、缺少锁定依赖或跳过测试会返回失败，不自动修改源文件。完整执行约十秒，具体耗时以当前记录为准。

[GitHub Actions](../.github/workflows/quality.yml)在新仓库 `main` 推送和 PR 时执行同一完整档。固定 Node 22.22.0、Python 3.11.14，使用 `npm ci`；只授予源码读取权限，无 AWS 凭证、部署权限或产物上传。测试阶段禁止外部网络，仅允许本机回环及明确替身；安装依赖、获取源码仍需正常网络。

CDK 检查在临时目录使用真实应用和 Agent／Worker／API 源码，媒体层明确标记 `SYNTHESIS_ONLY`。这让没有视频、FFmpeg、云输出或 SSO 缓存的干净克隆也能检查模板；**不会把占位媒体构建成可部署成品，不认证完整 SDK／FFmpeg 包、模型调用、GPU、线上播放或官方评分。** 实际部署仍须构建真实包并完成独立云端验收。
