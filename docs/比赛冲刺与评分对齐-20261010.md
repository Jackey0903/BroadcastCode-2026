## 3. 以评分影响排序的验收目标

以下是工程目标，不是新增官方要求或承诺得分。完成一项应补版本、输入、结果和证据；任何“已完成”都要对应实际结果。

### P0：准入、重跑和完整成片

1. **正式端到端恢复。** 从 `product/` 部署到正确账号，保留指定角色边界，不执行 bootstrap；登记输入并发布同源网页。至少一次正式真实任务完成 AgentCore 调用、工具读取、永久烧录与上传；浏览器播放到片尾并核对时长、音轨、哈希与拖动。
2. **官方接口适配。** 现场取得实际请求／响应与可运行样例，做薄适配层，不为等待 schema 停下已知闭环；契约到达后验证新输入与官方产物路径。不存在或无法确认的字段应返回明确错误，不能默认套用 Flagg／Amen。
3. **正式数据正确对应。** 每条数值保留原值、单位、事件及来源；视频播放器时间与比赛时钟分开。缺失、重复候选或冲突应被显式处理，不编造球员身份、官方指标和逐帧坐标。
4. **有效交付入口。** 提交真实可访问的 CloudFront URL，代码、部署与文档版本对应；考试作品为完整增强成片及可操作网页。20:00 前确认 Portal 保存成功，20:00–22:20 保持入口可用。

### P1：让评委看懂且相信

1. 主路径在一次短演示中完成：先看比赛、选关注点、慢放关键时刻、点回源帧、核对官方数据，再切换完整成片；所有按钮产生可见而有意义的结果。
2. 原片／成片切换与章节跳转维持正确时码；字幕和重点标记留出观看空间，轨迹只突出当前主线，历史站位与当前更新不混淆。
3. 创作区显示真实 jobId、状态、失败原因与工具记录；重试和读取已有结果分开。缓存或历史结果明确标识，不能用阶段动画代替执行。
4. 新输出先技术验收，再篮球内容复核；保留失败和内容拒收，不能将“MP4 已生成”直接写成“数据已准确”。

### P2：只做可证明的增量创新

优先完善已有的“注意力选择 + 关键时刻揭示 + 证据可回看”，而不是增加新的主页或菜单。新增能力必须说明它改善哪个评分项、如何验收、是否在规则范围内；没有正式输入支撑的整片轨迹复原、自动身份或因果指标不加入主线。当前俯视示意可作为来源清楚的补充展示，不抢完整成片、准确性和正式重跑的时间。

## 4. AWS 使用深度应由真实职责体现

|服务／组件|本产品要证明的专业使用|验收依据|
|---|---|---|
|AgentCore|真实承载 Agent，读取工具证据并经过多轮编排；每轮与任务关联|新正式 Runtime、实际调用与工具返回、耗时和输出记录|
|Bedrock|依据真实帧与官方快照生成解释；结构、时间和引用由程序核验|正式推理成功及真实模型 ID／输入／用量；错误和内容拒收可查|
|SQS + Worker|把耗时分析渲染与网页请求解耦，任务有可查询状态、失败与重试记录|同一 jobId 的队列处理、状态变化及真实失败路径；不重复创建推理任务|
|DynamoDB|持久记录任务进展和产物，使页面刷新后仍可恢复|按 jobId 查询真实状态，完成／失败均可读|
|S3 + CloudFront|输入、源帧、输出和生成记录有一致地址；完整网页和视频稳定交付|正式地址可访问、媒体哈希、Range／片尾播放；页面不引用失效旧账号媒体|
|CDK|定义实际资源、角色边界和依赖，代码与部署可对应|正式账号 synth／部署输出、依赖锁定文件与本次提交版本|
|CloudWatch／应用日志|把一个失败定位到具体任务、步骤与原因|由 jobId 关联实际日志，不用截图宣称从未发生的运行|
|FFmpeg 确定性渲染|把数据与解读烧录成完整可离线播放的视频，检查输入和输出|同一输出的标注、媒体信息、哈希与实际播放|

代码保持配置集中、职责清楚、依赖版本锁定、输入校验和错误可定位。针对变更运行有意义的测试，既有回归通过后把时间用于正式输入与浏览器验收；不要用不断堆相同测试数替代真实产品验证。官方机器重跑如何执行仍以实际契约为准。
