# 同步俯视球场：技术调研与实现边界

日期：2026-10-09。用户要求为桌面产品增加俯视球场、球员位置与行动轨迹，并与视频同步播放；随后明确可采用低精度、快速展示的最简实现。本文把现成技术、真实素材限制、局部实验和正式交付分开记录。没有调用 AWS 或使用外部 skills；另在隔离环境下载官方 YOLO11n，只作本地检测验证，未接入产品。

**后续全片更新：** 本文下方的局部实验记录属于早期版本。当前已按用户低精度展示要求扩展至完整21.548秒：31源帧编辑、10匿名名册、过去位置空心快照、9段球权与示意球路。轨迹仍为编辑插值，空中球未通过地面单应性投影，未知原始坐标仍为null。最新实现和184项测试/整段实际播放见[工程说明](../product/court-lab/README.md)与[全片证据](../product/evidence/court-full-20261009.json)。原范围核准状态未改变。

## 1. 结论与推荐路径

这类技术确实存在。按照用户最新的最简展示要求，本轮采用 **真实关键帧编辑大致脚点 → 球场地面标定 → 俯视点位 → 关键帧之间示意插值 → 按视频媒体时间回放**。无需训练、GPU 或新云服务。自动化升级可走检测与同镜头编号关联；困难在于转播画面中的相机移动、多人重叠、脚部遮挡与切镜。

不能承诺任意 NBA 单目视频里全程十人、姓名正确、坐标准确。现有官方 JSON 只有单次出手位置，没有其他九人的逐帧轨迹；不能用官方出手数据编出十人跑位。匿名追踪 ID 也不是球员身份。

本轮页面为独立 `/product/court-lab/`，本地弗拉格观看页有入口。页面标为“战术示意回放 · 依据画面编辑 · 非官方追踪数据”，保留遮挡和失败；未加入云端正式入口、不改变 Agent 协议，也不替代完整增强 MP4。

## 3. 对两段真实样片的检查

本轮实看 17 张现有关键帧，并读取媒体元数据、官方 JSON 和事件绑定。弗拉格 6–9 秒为首选候选宽镜头；9 秒最适合先标定。阿门 6–9 秒为备选，但右下脚部遮挡明显。稀疏抽帧判断还不等于全窗逐帧验收。

|片段|已观察到的问题|实现处理|
|---|---|---|
|弗拉格 0.2–3 秒|推进时部分球员画外|不补齐十人|
|弗拉格 6–9 秒|较宽半场，球场线清楚；有人重叠或近侧脚被观众遮住|先做地面标定；看不见接地点时标未知|
|弗拉格 12–15 秒|持续跟拍、缩放、底部图形遮挡|动态更新标定，不使用全片单个矩阵|
|弗拉格 16.5 秒|出手者跳起、篮下重叠|框底不是地面接触点，不能直接当准确位置|
|阿门 12–18 秒|紧镜头、脚点被比分牌盖住、部分球员离屏|中止缺失者显示，不强行重识别或延伸尾迹|
|阿门 21.288 秒后|人物近景切换|清空球场投影，不跨镜头连线|

## 4. 最快落地时应保留的技术约束

1. **位置来源**：优先足部地面接触点；身体中心、篮圈、篮架和空中球心不能直接按地面 homography 投影。
2. **标定**：至少四个非共线地面对应点，实际优先六至八个分散锚点及独立检查点。四点可以求解，但恰好拟合四点的零残差不能证明标定准确。NBA 球场尺寸和线条按 [NBA 官方规则](https://official.nba.com/rule-no-1-court-dimensions-equipment/)；不能使用足球或 FIBA 模板替代。
3. **跟踪**：只在同一连续镜头关联 ID；切镜重置。跨遮挡、相似球衣和人员交叉可能交换身份，需要核对。
4. **未知状态**：画外、遮挡、地面投影失败、特征丢失必须留下记录。插值与预测单独标示，不能冒充观察。
5. **同步**：以唯一的视频时钟为准；播放时使用 [requestVideoFrameCallback 的 mediaTime](https://developer.mozilla.org/en-US/docs/Web/API/HTMLVideoElement/requestVideoFrameCallback)，拖动、暂停、换片时同步重绘。不要另开计时器推进球员位置。
6. **输出**：保留原片哈希、视频时间、镜头段、匿名 ID、球队、图像点、球场点、状态、方法与核对状态；原片与俯视图可并排核查。
7. **暂缓指标**：没有定位精度验收前不显示跑动距离、速度、空间引力或战术因果，避免误差形成看似精确的统计。

初始默认 Python 已有 OpenCV 4.13.0 与 NumPy 2.4.2，没有 Torch、Ultralytics 或篮球检测权重。随后在被 Git 忽略的独立环境固定 Ultralytics 8.4.174、torch 2.9.1、torchvision 0.24.1，验证官方 YOLO11n 三张真实帧：9.0/9.5 秒可手工对应十人的身体框，10 秒右侧三人重叠合为一个框。观众、裁判也被检测，框底中心不等于接地点。详细结果见[检测实验](../product/evidence/court-detector-20261009.json)，复现与 AGPL-3.0 / Enterprise 许可边界见[独立检测说明](../product/court-lab/detector/README.md)。它不是本轮展示数据来源，也没有解决全员连续轨迹。

衣物光流实验也实际运行并保留：[失败诊断](../product/evidence/court-lab-diagnostic-20261009.json)。小数值残差未能识别错误脚点、串人及遮挡，部分候选经图像语义检查后拒收，`acceptedForShowcase=false`。没有将该实验作为准确追踪或最终展示。

## 6. 下一步验收与评分故事

推荐展示语义是“**同一回合，两个视角**”：左边看球和身体对抗，右边看空间关系，点击同一个编号让两边同时聚焦，再回到视频证据。短尾迹连结实际编辑锚点，并注明示意插值；不随机移动。可以帮助评委理解策展问题，但没有凭据时不宣称防守造成某个 xFG 变化。

完整升级顺序：局部投影实验 → 安装并固定检测模型 → 自动检测与同镜头跟踪 → 六至八点标定和独立误差核查 → 人员身份/遮挡复核 → 与原片同步验收 → 按规则核准范围接入产品 → 根据最终要求烧录进完整成片。选定三秒演示窗与支持任意新输入是两个不同验收目标。

实际结果见[本轮验收](../product/evidence/court-lab-20261009.json)：七张实际 PTS 关键帧覆盖 8.992–11.995 秒，十个匿名编号每条七点，可见人数 9/8/6/8/8/7/8。已有地面变换在末两帧失效后重新人工选角点；不冻结旧矩阵。所有坐标在界内，没有 clamp；遮挡留空，全部 estimated/reviewed=false。数据和标注可通过标准库生成器重建，详见[工程说明](../product/court-lab/README.md)。

145 项离线测试通过，包括媒体时钟、短窗终点、未知/切镜断线、半秒示意插值和来源校验。浏览器实际测试了同步慢放、筛选、聚焦、半场/全场、回到片段起点与区间外清空。曾发现真实 PTS 与浏览器微秒舍入导致终点尾迹消失，修复及测试记录保留。测试没有得到位置精度指标或自动化新输入认证。
