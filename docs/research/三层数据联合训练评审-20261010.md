# 三层数据联合训练评审：围绕同一视频事件选择、联接和解释证据

2026-10-10，北京时间。独立工程建议；本次只阅读现有代码、数据和官方说明，**没有启动训练、模型调用或部署**。范围仅火箭 HOU 与独行侠 DAL。本文不修改正在运行的 v4，也不宣称下面的联合能力已经实现。

## 1. 建议改变训练目标

下一轮目标应是：**给定一个已对齐的视频事件与用户问题，选择必要工具，取得基础事实、效率背景和深度指标，用可追溯的关系解释这一拍。** 单独提高 xFG 估计精度只能覆盖其中一小部分。

当前 [v4](../../product/rl/scout_env.py) 主要把官方出手记录映射成同类出手的中位数与区间；它没有看视频，也没有学习综合球员表现。两队联合统计表的 H2H MAE 已为 0.0910，训练前 3B 已接近这条线，不能据此认定 RL 已有增益。继续用大部分算力逼近一张参考表，收益不足以支撑“理解比赛”的产品目标。应保留其为一个辅助工具与可复现对照，把后续主要投入转向证据选择、跨表关联和解释边界。

现有 [depth_tasks.py](../../product/rl/depth_tasks.py) 已有 410 道真实来源检索、差值与缺失/粒度任务，但一次主要处理一个指标，输出不允许自由文本。它能作为联合训练的底座；尚不能直接宣称模型已经理解基础数据、传统高阶与深度指标之间的关系。

## 2. 三类数据怎样共同回答一个问题

|层次|在同一事件中的职责|优先字段或来源|当前边界|
|---|---|---|---|
|基础事实|确认谁、哪场、哪次动作、结果，以及已知比赛背景|gameId、eventId/actionNumber、playerId、出手类型、节次；真实 box score 的 PTS/FGA/FGM/3PA/3PM/FTA/FTM/AST/TOV/MIN；经核对的画面锚点|两片事件已对齐；不能把出手事件号当视频秒数，空时钟保持未知|
|传统高阶|补充表现效率、使用角色和球队环境|优先官方 TS%、eFG%、USG%、球队 OFF_RATING/DEF_RATING/NET_RATING；均带统计区间与适用对象|目前未进入 RL 观察或工具；必须先取到真实来源与字段。不可从不完整的主力出手样本伪算球队效率|
|深度赛场|补充该次机会质量以及球员赛季防守关注/影响力背景|事件 xFG；赛季 Gravity、Leverage、Shot Difficulty 的明确子项|已取得两队 Gravity18人、Leverage20人、ShotDifficulty8人；后两类不可冒充本事件测量|

传统高阶的术语与公式以 [NBA 统计词典](https://www.nba.com/stats/help/glossary) 为准；首先核实数据接口、对象与时间范围，再生成训练答案。NBA/AWS 对深度指标的官方定位见 [合作说明](https://pr.nba.com/nba-aws-partnership/)。具体已取得字段、单位疑点和联接规则见 [深度数据研究](../rl-depth-data-research-20261010.md)。

训练重点不是把三张卡片并排显示，而是学习以下**有条件的关系**：

- **产量与效率互补**：PTS 或出手次数说明比赛中的累计表现；效率背景帮助解释相同产量用了多少机会。只比较相同口径，不能把某次进球当作高效率的证明。
- **个人效率与机会质量不同**：同赛季、同统计口径的 FG% 与平均 xFG 可以作来源明确的差值；不能拿 TS% 减单次 xFG 命名“超额命中率”，也不能用赛季 FG%+ 证明某次出手一定能进。
- **使用角色与防守关注互补**：有来源的使用率背景可与赛季持球/无球引力并列解释角色；二者不能互相替代，不能用其中一个推算另一个。
- **基础贡献与 Leverage 子项互补**：助攻、篮板等基础记录可与相应赛季影响力子项一起帮助选择关注点；只有赛季分值时，不给当前动作分摊胜率变化。
- **画面事实与统计背景连接**：连续画面可支持“防守者在此时向持球侧移动”这一观察；赛季引力可以解释为什么值得关注该球员的防守待遇。它不能证明这次移动由其引力造成。

示例成品结构：先给本事件真实动作与官方 xFG，再给一项真正相关的效率背景，最后按问题选择 Gravity 或 Leverage 背景并说明范围。没有可用的高阶字段时明确缺失，仍完成已有事实；不补造数字。上述关系是待实现的解释规则，不是本轮新得出的篮球因果结论。

## 3. 先做结构化“证据关系”，再生成播报文字

工具建议复用现有后端，按用途封装为：`event_lookup`、`boxscore_lookup`、`efficiency_context`、`official_depth_lookup`、`situation_reference`。已随请求可靠提供的事实不必再次查询；只查回答所需的字段。每题最多三轮、四次工具调用作为初始预算建议，超预算仍能返回已取得事实和限制。

联合答案至少包含以下字段，不让模型用一段流畅文字掩盖错表或错粒度：

|字段|内容与核验方式|
|---|---|
|`eventKey`|gameId/eventId/playerId；逐项对比事件注册表|
|`mode`|`posthoc_snapshot` 或 `historical_as_of`；与用户问题一致|
|`claims[]`|每条有 id、metric、value、unit、entity、grain、period、dataAsOf、sourceId、sourceHash、rowKey、claimType|
|`claimType`|`official_fact`、`video_observation`、`derived_arithmetic`、`model_interpretation`、`limitation`|
|`relations[]`|引用 claimIds，使用允许的关系码，如 `volume_efficiency_context`、`quality_execution_difference`、`role_attention_context`、`contribution_context`；注明 `association_only`|
|`missing[]`|字段、原因码、影响；单位未知、时间不符、粒度不符和无来源分别记录|
|`focusSuggestion`|建议回看哪一已知画面锚点、对应哪些证据；属于模型建议，不是官方标签|

第一版解释文字由固定模板或 Claude 将通过校验的结构表达出来，不能增加新数字、新球员身份、无证据因果或新时间点。涉及视觉的事实必须链接实际帧/片段；纯数据题不伪装成视觉理解训练。开放文本的篮球质量另抽样评审，不能以结构化奖励满分替代。

## 4. 建议训练配比与角色

下面是**新的联合任务采样占比**，不是当前 410 题的实际分布。只用真实两队记录派生问题和答案，不以改写次数冒充独立比赛数量。

|任务|占比|策略应学会什么|
|---|---:|---|
|事件对齐与基础事实|15%|选对比赛/球员/出手，必要时查事件或 box score，拒绝错配|
|基础事实与传统高阶关联|20%|区分累计产量与效率/角色，完成同范围合法比较；缺字段不自造|
|跨层关系解读|35%|按问题选两层或三层证据，输出有来源的关系；其中只在证据齐全且问题相关时用全三层|
|缺失、时间与因果反例|20%|区分无数据与零、赛季与事件、赛后快照与赛前截止；抵抗错误诱导|
|xFG 隐藏标签辅助任务|10%|保留 v4 的中位数/区间目标和训练引用隔离，作为可量化辅助能力|

不设“三工具调用成功”奖励。简单事实题一项工具就足够；多工具价值必须体现为更完整且准确的必要证据。`lookup` 题允许复制查到的官方值，这是检索成功；隐藏标签估计题必须由独立工具白名单阻断该值，两种成功率不得混为一谈。

**短期推荐角色：Claude 负责现有画面观察、导演与最终表达；3B 学结构化工具选择和证据组装；程序负责身份联接、数值计算、来源校验与渲染。** 当前 3B 是文本模型，不能靠增加表格字段获得视觉能力。先用现有 Claude 工具链形成可用联合产品，再决定小模型是否能以更低成本承担同一结构化任务。

建议顺序：

1. **先做可运行的固定策略和 Claude 同工具基线。** 约 60 个开发任务覆盖五类需求，全部来源固定；先检查联合输出是否对用户有用。工具源未齐前不启动新 GRPO。
2. **小规模 SFT 学协议。** 用约 250–400 条来源校验通过的真实工具轨迹训练一个短轮次；混入单工具、多工具、无需额外查询及正确拒答，禁止把私有 oracle 放进模型观察。轨迹优先程序生成，Claude只做受校验的表达和规划示范；改写按原事件分组。
3. **短 GRPO 学选择与纠错。** SFT 在冻结开发集结构有效率达到建议门槛 95% 后，才做一个有明确时长上限的小实验；保留当前 temperature=1、真实工具 trace、动态去平组等已验证约束。不要同时开多条主要只学数值拟合的训练线。
4. **依同题结果决定上线角色。** 新3B若没有在成功率、证据边界或成本上优于SFT/Claude工具基线，就保留Claude联合链路，3B成果如实展示为实验。旧v4可完成当前实验并作为辅助工具候选；本规划不自动下达停止或部署指令。

## 5. 可程序核验的奖励与防刷分

`depth_tasks.score_answer` 的真实 trace、来源 hash、错误范围硬惩罚可直接继承；联合任务扩展为按 claim 与 relation 核验，而不是由一个 LLM 对整篇文案打“感觉分”。

对合法输出，建议初始奖励：

`R = 0.30×事实正确 + 0.25×证据正确 + 0.20×必要信息覆盖 + 0.15×关系正确 + 0.10×格式正确 − 0.002×实际工具调用数`

- **事实正确**：相同事件/实体/时间范围下的数值、符号、单位和可用状态逐项校验；容差按每个来源显示精度设置，不能给所有指标统一百分比容差。
- **证据正确**：引用必须出现在执行器记录的真实返回中，核验 `sourceId/hash/rowKey/grain/period/asOf`；模型自己写一段“我已查过”的轨迹不得得分。
- **必要信息覆盖**：分母由冻结任务的答案需求决定，不由模型实际写了几项决定。覆盖缺失原因可得对应分，省略一个可回答的关键事实不得通过缩小分母拿满分；不按工具数或指标数量加分。
- **关系正确**：只对允许且有完整操作数的关系码评分。例如合法同范围差值、角色背景对照、观察与赛季背景的非因果连接。术语解释题也需选对指标职责，不能拿“全部是相关性”作万能答案。
- **硬错误**：错事件/错球员、伪造来源、未来信息冒充赛前、把赛季值冒充事件值、把未知当零、无依据因果，整题奖励固定为负值（建议 `−1−工具成本`）；不能用其他正确字段抵消。
- **防省略与乱查**：所有题都拒答会在可回答题失分；返回一堆无关指标增加错误与成本；允许同一事实来自多个经验证等价来源，避免强迫唯一调用序列。工具成本最初保留0.002，再用固定策略期望奖励核算是否压倒真实收益。
- **防模板猜答案**：在开发评测加入错队/错赛季干扰记录、相近球员ID、正负分值、缺失项、合法同名不同单位；反事实数字替换仅作清楚标注的协议测试，不包装成官方比赛样本。

xFG 的 10% 子任务继续独立使用 v4 未截断数值奖励并单列 MAE/区间评分；联合解释任务中展示官方 xFG 是查询事实，不能因为照抄标签而记一次“预测正确”。

## 6. 缺失、as-of 和持出划分

每条数据分别保存 `retrievedAt` 与 `dataAsOf`。前者是抓取时间，后者才是统计截止。当前赛季深度快照没有可靠历史截止，因此可用于明确标注的赛后背景解读；收到“截至本场开球前”问题时返回不可用。视频中的一场事件与赛季背景可同屏，但不得让用户误以为后者是赛前已知。

保持 HOU/DAL 范围；当前数据中的球队标签是来源快照归属，历史转队身份需由事件侧核验。传统高阶必须区分球员、球队、在场阵容以及统计周期；不把球队效率当作某个球员的单独贡献。

**分割先于派生问答。** 同一事件的不同问法、同场不同事件、同条源数据的改写不得散落训练与测试。事件任务按整场分组；现有四场390次 H2H 已用于开发，继续标为开发评测。检索任务另按球员分组并持出问题模板/指标组合；持出球员的官方行可由检索工具提供，因为考的是检索与联接，不是背诵该球员数据。隐藏标签预测维持整场排除的交叉参考表，并屏蔽完整赛季结果统计。

两段视频只能支持两段端到端内容验证。其他已采集出手记录可构造数据事件任务，但没有视频的记录不能计作“看视频理解成功”。新正式素材若到达，保留为新的交付验收，不再据其反复调奖励。

## 7. 一次小型评测即可回答是否值得继续

建议在同一批约120个冻结数据任务、两段视频验收上比较：固定规则、Claude同工具、3B SFT、3B SFT+GRPO。120是短期预算建议，不是已经完成的测试数量。先报告致命事实/粒度错误，再报告整题成功率、必要信息覆盖、正确缺失率/错误拒答率、工具调用与时延；开放文字另作少量盲评。模型选择至少要求没有已知关键来源错误；目标整题结构有效率≥99%，未达到就维持已有产品角色。

三类数据的消融使用同题、同模型、同预算，屏蔽相应工具：

|条件|回答的问题|
|---|---|
|基础事实 B|没有背景时能否准确确认事件|
|B＋传统高阶 A|是否增加了有据的效率/角色解释|
|B＋深度 D|是否增加了机会质量/防守关注/影响力解释|
|B＋A＋D|是否带来前两种不能单独完成的正确关系与有效信息|

基础事实是事件联接前提，不设计没有事件身份的“深度预测结果”冒充同题。屏蔽某层时允许正确说明缺失，但该条件仍因缺少可回答内容而在**必要信息覆盖**上失分；否则“任何题都说不知道”会让消融看不出价值。额外做一组错误来源/错粒度干扰，验证联合输入更多时没有更容易编造因果。

发布时应能展示一个清楚的前后对比：基础版知道这一拍发生了什么；联合版还知道该查哪种背景、如何与这一拍建立有限关系，以及哪里证据不足。**这是下一阶段要验证的产品增益；GPU训练曲线或更低的xFG表拟合误差不能替代它。**

## 8. 可直接交接的最小实施顺序

1. 数据负责人先补两队真实 box score 与传统高阶来源，明确字段、分母、时间范围和缺失；没有取得的字段不写训练标签。
2. 后端把事件键、三类来源与视觉锚点整理为统一证据对象；复用 `depth_tasks` 的范围检查与真实 trace，新增关系码和错误反例。
3. 用固定策略与Claude输出一版结构化联合解读，先在两片做内容核对；前端仅接收已核验的事实、范围与回看建议。
4. 数据和产品价值都成立后，再做一次小SFT及短GRPO；三类消融和同ID比较各做一次，结果不足就调整任务而不是继续堆训练时长。

本阶段无需更多模型规模、轨迹复原或外部球队训练数据。优先把当前已有的准确事件、两队背景与官方深度数据连接成可信且易懂的解释。
