# 火箭／独行侠三层官方数据可用性核查

核查日期：2026-10-10（Asia/Shanghai）。范围仅 HOU `1610612745`、DAL `1610612742`。本次为只读、少量公开 GET 的可用性调查，没有训练、部署或扩大采集。本文区分已返回的数据、页面声明的字段和工程推导值；失败访问不是数据不存在的证明。

## 核心结论

现在可以立即联合使用的是：基础事件与身份信息、逐出手 xFG 标签、两队的赛季引力／leverage／投篮质量快照。传统高阶 TS%、eFG%、USG%、ORTG、DRTG、AST%、Pace 等尚未取得可验证的官方数值响应；当前 RL 也没有使用这些传统高阶指标。NBA 中国官方页面及脚本证明相关高级球队字段／接口曾存在，但本次实际 GET 失败，不能记为已接入。

推荐先把三层数据放进同一证据仓库、统一来源与时间边界，再分两条任务：赛后事实解释可查同一快照；出手 xFG 估计只能使用该出手之前的基础／高阶历史和训练折内先验。2025-26 全季引力、FG%+、平均 xFG 不能作为同季留出出手的预测特征。

## 传统高阶指标：已发现与已取得的区别

### 官方页面与访问实测

1. [NBA 中国高级球队统计](https://china.nba.cn/statistics/advancedteamstats/) 本次 HTTP 200，返回 58,228 字节旧版 Angular 页面。页面模板声明 `EFG%`、`trueShootingPct`、`usagePct`、`offRtg`、`defRtg`、`DREB%`、`OREB%`、`REB%`、`Pace`、`Possessions`、`turnoverRatio`、罚球率及助攻／非助攻出手占比等字段。返回 HTML 中是未填值的模板，不是已取得的高级统计数值。
2. 页面加载的[官方脚本](https://res.nba.cn/scripts/custom.min.js) 明确 `Site.apiDomain='/stats2/'`，声明 `league/advancedteamstats.json`、`league/advancedteamstatsform.json` 等 feed；控制器从 `seasonStats`、球队 `statAverage/statTotal` 和相应高级字段读取数据。本次逐一访问下列三个公开路径均返回 **HTTP 504**：
   - `https://china.nba.cn/stats2/league/advancedteamstatsform.json`
   - `https://china.nba.cn/stats2/league/advancedteamstats.json`
   - `https://china.nba.cn/stats2/league/playerstatsform.json`
3. [NBA.com 球员高级统计](https://www.nba.com/stats/players/advanced) 可以读到筛选页面，但本次返回内容没有可验证的球员数值行。页面支持赛季、球队和 Date From/Date To 的 UI，不意味着本地已经能稳定调用其数据 API。带球队／赛季筛选的页面读取也未取得数值。
4. [NBA 中国当前页面脚本](https://res.nba.cn/static/webmaster/assets/js/index-8c467dd5.js) 使用 `BASEAPI='https://api.nba.cn'`，声明 `/sib/v2/league/statsform`、`/sib/v2/league/playerstats`、`/sib/v2/league/teamstats`、`/sib/v2/teams/stats/aggregation`。所见播放器／球队字段为基本得分、投篮、篮板、助攻等，未发现传统高级值的可靠返回证据。对公开 `https://api.nba.cn/sib/v2/league/statsform` 的普通 GET 返回 **HTTP 400**；没有尝试绕过请求限制。
5. NBA 官方 liveData boxscore 两个目标比赛路径的普通 GET 均返回 **HTTP 403**：`https://cdn.nba.com/static/json/liveData/boxscore/boxscore_0022500701.json` 与 `...0022500491.json`。未绕过限制；不能列为本环境已验证可用的数据渠道。

结论：当前可可靠复用的是已经保存并带来源 SHA 的本地官方快照。传统高阶的可靠数值获取路径尚缺；下一阶段应先从官方网页正常交互／主办方提供的两队数据导出取得一个真实成功样例，再决定采集器，不能围绕失效接口搭大规模任务。

### 两队应该补的数据及计算边界

| 需要补充 | 首选官方粒度与主键 | 当前状态／可行替代 |
|---|---|---|
| FGM/FGA/3PM/3PA/FTM/FTA/PTS/MIN/OREB/DREB/REB/AST/TOV/STL/BLK | 两队球员单场 boxscore：`gameId + teamId + playerId`；球队单场总计 `gameId + teamId` | 当前没有完整可靠两队赛季缓存；先补它，才有传统高级的基础分母 |
| TS%、eFG% | 球员／球队 × 查询起止日；保留总计再算比例 | 取得基本总计后可自行计算。TS = PTS/[2×(FGA+0.44×FTA)]；eFG = (FGM+0.5×3PM)/FGA。必须标为按官方公式计算的派生值，不冒充官方返回字段；分母为零输出空值；不能平均每场百分比 |
| AST%、USG%、OREB%/DREB%/REB% | 官方球队／球员高级单场或明确时间窗口；需相应在场机会分母 | 没有完整 on-court／机会分母时，不用球员÷球队全场总计假装官方百分比。AST/TO 可另算，但不改名 AST% |
| ORTG、DRTG、NETRTG、Pace、Possessions | 球队单场可做最小版本；球员版本需要在场 possessions | 当前未取得官方原值。简单估算回合只能显式命名 `estimated_possessions/estimated_off_rtg`，和官方 rating 分列；不把估计值当官方标签 |
| 防守 matchup／事件压力／事件引力 | 单事件需要 `gameId + eventId` 和实际来源字段 | 目前 `inside/def?gameId=0022500701` 返回 `data:null`，不能从赛季聚合反推。任务应正确拒答，保留赛季尺度解释 |

指标定义依据：[NBA Stats Glossary](https://www.nba.com/stats/help/glossary)、[NBA Stats FAQ](https://www.nba.com/stats/help/faq)。深度定义依据：[NBA Inside the Game Glossary](https://www.nba.com/news/inside-the-game-stat-glossary)、[NBA 中国深度赛场术语](https://china.nba.cn/inside-the-game/glossary)。本文只引用公式和字段含义，不把网页宣传当数据可访问证明。

## 最小联合数据契约与下一阶段顺序

每行统一存：`source_url/source_sha256/retrieved_at/provider_as_of/season/season_type/grain/team_id/player_id/game_id/event_id/unit/value/status`。`provider_as_of` 未返回就为空，不能用抓取时间替代统计截止日；当前两队关联采用 `snapshot_team_id`，另存逐场 `event_team_id`。

1. 先把上述已有基础＋深度资料接成只读官方工具，返回原值、来源、时间范围、缺失原因。已有 [410 个离线深度任务方案](../../product/rl/results/depth-task-plan-20261010.json) 可立即验证查询、同口径比较和拒答，但未训练，不等于已进入 GPU。
2. 补一个已核验 HOU-DAL 比赛的官方完整 basic boxscore 和 advanced 返回样例；成功后只采集两队所需比赛，记录真实日期覆盖、球员转队与 DNP。历史特征截止到目标比赛前一场。
3. TS/eFG 可在基础数据齐全后先做有出处的确定性派生；USG/AST%/rating/pace 等在获得官方原值或完整机会分母前保持 unavailable，不以替代量混名。
4. 联合解释任务可问“该球员本窗口投篮效率如何，官方平均 xFG 与实得 FG% 差多少，同一快照无球引力如何”；三个答案各自标明时间粒度，不把相关性变因果，不将赛季引力用于单次事件结论。
5. xFG 估计线保持目标隐藏，基础／高阶历史特征只能来自比赛日前；同季全季 depth 快照仅作独立检索解释任务。奖励正确取值、算术、来源边界和必要拒答，不奖励工具调用次数。训练/验证按整场及时间切分，避免同场泄漏。

当前 RL-SCOUT 是文本工具型 CausalLM 的策略训练，不是视觉模型训练；后续可消费由视觉链路定位后的官方事件，但不能把这份数据工作称为提升了视觉权重。
