### F. 关键结论与教训（讲解“实现深度”可用）

1. **v0 坍缩**：平方校准 + 每个工具 0.03，多调工具的收益 < 0.01，最优解是只调区域参考、照抄均值；8 条轨迹完全一致 → 组内优势 0 → 梯度 0。
2. **v1 仍坍缩**：线性校准斜率 1.5（×0.75），动作表只降 0.005 MAE（折合 0.008 奖励）< 0.01 成本。**规则：工具成本必须小于“该工具带来的误差改进 × 校准斜率 × 权重”**；改奖励前先离线核算各固定策略的期望奖励。
3. **组内一致意味着该组当步优势为零**，不等于模型永久停止学习；后续采样、其他组与优化器状态仍可能改变策略。v1 第 90 步的改善已反驳旧表述。v2 起记录 `flatGroups`，v3 加动态采样；v4 先打乱题序再选有效组。
4. **旧线性混合只是有限基线，不能称信息上限**（0.094/0.090）：可用特征里没有逐次出手的防守人距离（`def` 接口返回 null、`gameClock` 为空），官方质量值的剩余差异来自这些看不到的追踪因素。两队球员/对手先验离线不降误差 → 复杂奖励挤不出数据里没有的信息。
5. **不确定性是真正没用上的信号**：离散度相差 5 倍，固定 ±0.08 的“比常态更难”阈值对三分几乎不触发、对篮下几乎总触发 → v3 学区间。
6. **采样输出是对抗性的**：解析函数绝不能抛异常（v2 首次失败的原因）。
7. 外部约束：Bedrock 导入被 SCP 拒绝（用 SageMaker 端点）；g6e 无容量（用 g5）；NBA 美国接口 403、中国 `pbp/details` 需签名（没有逐回合事件链与比分/时钟）。

### G. v3「区间球探」设计（用户 11:30 提出“聚焦两队 + 更完整的奖励”；Claude 依据 E 节离线验证定稿，用户尚未逐项确认）

- **输出**：`{"quality": q, "low": l, "high": u, "reason": "…"}`，要求 0 ≤ l ≤ q ≤ u ≤ 1；`[l,u]` 是同类出手官方质量的 60% 中心区间（第 20–80 百分位）。
- **工具**：`zone_reference`、`move_reference` 额外返回训练集第 20/80 百分位与标准差；`player_profile` 不变；新增 `player_zone`（出手人在该区域×两分/三分的训练集历史：均值、百分位、样本数；主要覆盖火箭/独行侠档案球员）。离线它不降点误差，模型应学会“何时值得调”——这本身是可验证的学习结果。
- **奖励 v3**：`R = 0.45·Cal + 0.30·Int + 0.15·Fmt + 0.10·Grd − 0.002·工具数 − 0.2·无效`
  - `Cal = max(0, 1 − |q − y|/0.5)`（同 v1/v2）
  - `Int = max(0, 1 − IS/1.5)`，`IS = (u − l) + (2/α)(l − y)⁺ + (2/α)(y − u)⁺`，α = 0.4。未截断的区间评分具有恰当评分性质；**v3 的 max(0, ...) 截断破坏该保证**，不能据此声称不会刷分。v4 已改为无截断仿射奖励（I 节）；此处仅保留 v3 历史公式。
  - `Fmt` 额外要求 l ≤ q ≤ u；`Grd`、工具成本、无效罚分同 v2。
- **训练**：每步采样 12 题，丢弃组内奖励完全相同的组，保留至多 8 组有信号的组更新（DAPO 式动态采样）；80% 两队样本；其余超参同 v1/v2。
- **评测**：MAE、平均区间评分、60% 覆盖率（理想 0.60），对照“区域分位数区间”0.35/0.32 与“固定 ±0.08”0.41/0.39。
- **产品**：`label` 改为区间判定——官方值 < l 为 `tougher`，> u 为 `easier`，否则 `typical`；字段新增 `low/high`，原字段不变，旧调用不受影响。
- **版本一致性**：提示词与工具集按版本登记（`POLICY_SPECS`）；`reference_tables.json` 写入 `"spec"`，`Scout` 按它选提示词。**端点上的模型与 Worker 打包的参考表必须同一版本**；换模型时两者一起换（参考表由 Codex 打包进 Worker）。

## 3. 智能体环境、动作与奖励（可验证奖励 RLVR）

**一回合（episode）= 一次出手。** 状态只给出手描述、两分/三分、侧别、距离与区域、节次、出手人编号；**不给官方质量值与命中结果**。

**动作**：第一轮可直接作答，或请求工具（可同时请求多个）；工具结果返回后第二轮必须作答。最多两轮。

|工具|返回|来源|
|---|---|---|
|`zone_reference`|该区域 × 两分/三分的联盟平均官方质量与样本数|仅训练集统计|
|`move_reference`|同一出手描述（如「突破漂移跳投」）的平均官方质量与样本数|仅训练集统计|
|`player_profile`|出手人赛季档案；不在档案内则返回不可用|官方赛季档案|

**作答格式**（JSON）：`{"quality": 0~1, "reason": "≤60字，只能引用输入与工具结果中的事实"}`。

**奖励**（全部由程序计算）：

|项|计算|权重|
|---|---|---:|
|校准|**v1**：`max(0, 1 − |q̂ − y|/0.5)`，与报告指标（平均绝对误差）一致；v0 为 `1 − ((q̂ − y)/0.4)²`|0.75|
|格式|最终输出为合法 JSON、字段齐全、数值在 [0,1]|0.15|
|有据|理由中的数字必须出现在状态或工具结果里，否则判 0|0.10|
|工具成本|**v2**：每调用一次工具 −0.002（v1 为 −0.01，v0 为 −0.03）；不存在的工具或格式错误 −0.2|扣分|

希望学到的行为：会调用真正有用的工具、把多个先验合理组合、少调无用工具、不编数字。指标会单独记录工具调用率的变化。

{"available": true, "typicalQuality": 0.51, "reason": "...", "toolsUsed": ["zone_reference", "move_reference"],
