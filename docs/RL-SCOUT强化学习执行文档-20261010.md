## 0. 一句话

用**官方出手质量数据（NBA 基于球员追踪的深度算法结果）**做可验证奖励，在 SageMaker GPU 上用 GRPO 训练一个会调用工具的小模型「球探」，让它学会估计**同类出手的常见质量**；运行时与官方值对比得到「**难度差**」，驱动导演 Agent 的回放与空位提示，并在网页「训练营」和成片 HUD 中可视化。训练预算 **≤ 2 小时**。

## 2. 数据：官方深度数据，不编造

来源全部是 NBA 中国官方接口，本机已实测可用（美国 CDN 与 stats 接口本机 403/超时，不作依赖）：

|接口|内容|用途|
|---|---|---|
|`inside/game?date=`|当日比赛列表|枚举 2025-26 常规赛比赛|
|`inside/season/shotDifficulty?season=2025-26&teamId=`|每队约 5 名主力的赛季档案：平均出手质量（总/两分/三分）、命中率高出期望、平均防守人与球距离、防守压力分|球员档案工具；确定抓取对象|
|`inside/gpShot?gameId=&playerId=`|该球员本场每次出手：出手描述、两分/三分、左右侧、全场百分比坐标、节次、命中、**官方出手质量值**、事件号|训练样本与奖励目标|

- 坐标换算：`locX/locY` 为全场长/宽百分比；右侧篮筐 x=88.75ft、左侧 5.25ft、y=25ft，换算出手距离与区域（篮下/禁区/中距离/底角三分/弧顶三分）。已用样本核对：三分 24.7ft、中投 18ft。
- 规模目标：约 60 场、7000 次出手（只覆盖档案内主力；无比赛级球员名单接口）。
- 切分（10:35 按用户建议改为聚焦两队）：**测试集 A「模拟考场」= 火箭 vs 独行侠全部交手比赛**（含两段练习片比赛 0022500491、0022500701，及 0022500356 等），整场不进训练，防止模型背下考试同场出手、让难度差失效；**测试集 B「泛化」= 3 月起不涉及两队的比赛**。训练集 = 两队其余全部比赛（不限日期）+ 3 月前全联盟比赛；训练采样 80% 来自两队比赛、20% 全联盟。参考表仍用全联盟训练集统计。
- 已知边界：赛季档案是全季汇总，含测试期信息，评测会注明；官方质量值包含防守等追踪因素，**仅凭出手类型和位置不可能精确预测**，模型学习的是条件平均（常见质量）。
- 视频：两段练习视频规模太小（2 段），**不用于训练**；用于运行时 Agent 环境与端到端评测。

## 3. 智能体环境、动作与奖励（可验证奖励 RLVR）

**一回合（episode）= 一次出手。** 状态只给出手描述、两分/三分、侧别、距离与区域、节次、出手人编号；**不给官方质量值与命中结果**。

**动作**：第一轮可直接作答，或请求工具（可同时请求多个）；工具结果返回后第二轮必须作答。最多两轮。

|工具|返回|来源|
|---|---|---|
|`zone_reference`|该区域 × 两分/三分的联盟平均官方质量与样本数|仅训练集统计|
|`move_reference`|同一出手描述（如「突破漂移跳投」）的平均官方质量与样本数|仅训练集统计|
|`player_profile`|出手人赛季档案；不在档案内则返回不可用|官方赛季档案|

**作答格式**（JSON）：`{"quality": 0~1, "reason": "≤60字，只能引用输入与工具结果中的事实"}`。

**奖励**（全部由程序计算）：

|项|计算|权重|
|---|---|---:|
|校准|**v1**：`max(0, 1 − |q̂ − y|/0.5)`，与报告指标（平均绝对误差）一致；v0 为 `1 − ((q̂ − y)/0.4)²`|0.75|
|格式|最终输出为合法 JSON、字段齐全、数值在 [0,1]|0.15|
|有据|理由中的数字必须出现在状态或工具结果里，否则判 0|0.10|
|工具成本|**v1**：每调用一次工具 −0.01（v0 为 −0.03）；不存在的工具或格式错误 −0.2|扣分|

希望学到的行为：会调用真正有用的工具、把多个先验合理组合、少调无用工具、不编数字。指标会单独记录工具调用率的变化。

## 4. 训练

|项目|设定|
|---|---|
|基座|`Qwen/Qwen2.5-3B-Instruct`（Apache-2.0）；冒烟测试用 `Qwen2.5-0.5B-Instruct`|
|方法|GRPO：每题采样 8 条轨迹，组内标准化优势，单次更新（on-policy），不加 KL；LoRA r=32 作用于全部线性层|
|实现|自写精简 GRPO 循环（transformers + peft），支持两轮工具对话、只对模型生成的 token 计损失；不依赖 TRL/vLLM 版本|
|机器|SageMaker 训练任务 `ml.g6e.2xlarge`（1×L40S 48GB），复用练习时跑通的 PyTorch 2.9 官方镜像方式；执行角色 `NBAHackathonWorkloadRole`|
|预算|每步 8 题 × 8 轨迹；约 150–200 步；`MaxRuntimeInSeconds` 设 2.5 小时硬上限|
|检查点|`/opt/ml/checkpoints` 持续同步到 S3：每 25 步 LoRA、`metrics.jsonl`、`rollouts.jsonl`（训练营页面用），训练结束输出合并模型文件|
|日志|每步打印奖励与分项，CloudWatch 可见|

**Codex 接入需要做的事**（Codex 范围，Claude 不改）：
1. AgentCore 运行时（或调用球探的组件）执行角色增加：`sagemaker:InvokeEndpoint`，资源 `arn:aws:sagemaker:us-east-1:555726205424:endpoint/rl-scout`（CDK 中加 policy statement，保持权限边界）。
2. 打包进 Agent：`product/rl/scout_env.py`、`product/rl/scout_client.py`、`product/rl/data/reference_tables.json`（运行时工具表，只含训练集统计与官方档案，约 60KB）。
3. 在 Agent 读到官方出手记录（gpShot 行：`shotDesc/shotType/side/locX/locY/period/value`）后调用：
```python
from scout_client import Scout, sagemaker_invoker
scout = Scout(sagemaker_invoker("rl-scout"), tables_path="reference_tables.json", model_name="rl-scout-qwen2.5-3b")
result = scout.analyse(official_row, player_id, official_quality=official_row["value"])
```

请求：官方 gpShot 行 + 出手人编号 + 官方质量值。返回：
```json
{"available": true, "typicalQuality": 0.51, "reason": "...", "toolsUsed": ["zone_reference", "move_reference"],
 "difficultyDelta": -0.065, "label": "tougher",
 "model": "rl-scout-qwen2.5-3b", "source": "AI 估计（强化学习球探）"}
```
- `difficultyDelta = officialQuality − typicalQuality` 由代码计算，不让模型写；`label`：< −0.08 为 `tougher`（比常态更难），> +0.08 为 `easier`（比常态更好的机会），其余 `typical`。
- 官方值始终从官方数据直接复制显示；球探值只标「AI 估计」。措辞只陈述差值，**不写因果**（不写“防守失误导致”）。
- 失败或超时：返回 `{"available": false, ...}`，主流程照常完成，成片不显示 SCOUT 层。端点单次推理约 1–3 秒（3B，贪心解码，最多两轮）。
