## 用户能看什么

建议队友在球员详情中提供“进攻 / 防守 / 对比”三个入口。短视频每段只显示一至两项与解读相关的指标；其余可在网页展开。点选对手后先显示“对手球员背景”，防守人身份经单独核实后才能标“本回合防守者”。

|部分|已支持内容|统计范围|
|---|---|---|
|进攻基础|得分、命中/出手、三分、罚球、助攻、失误、进攻篮板|本场赛后完整统计|
|进攻效率|eFG、TS、投篮/三分/罚球命中率、助攻失误比、三分出手占比|由同场官方计数计算|
|进攻深度|总体与持球/无球、内线/外线引力；进攻、投篮、创造机会Leverage|2025–26赛季快照|
|防守基础|抢断、盖帽、防守篮板；出场时间、总篮板单独列通用统计|本场赛后完整统计|
|防守深度|DEF_LVG防守影响力、ON_BALL_DEF_LVG持球防守影响力|同一赛季快照的来源分数|
|投篮背景|实际命中率、预期机会质量、超预期命中率、两分/三分机会质量、平均承受防守压力|投篮球员的赛季背景|
|比较|同指标左右并排与差值；同一球员赛季实际与预期命中率差|同场或同赛季、同来源快照、同单位|

REB_LVG、TOV_LVG、TOT_LVG作为综合影响力单列，不把总影响力当作纯防守。压力分是该投篮球员面对的压力，不是他的防守能力。防守距离单位未确认，本次不展示；USG/ORTG/DRTG仍缺失。

## 给后端的直接接口

新增标准库模块[球员对比](../product/rl/player_comparison.py)。沿用已交付的`evidence_store.py`、`evidence_env.py`、`depth_tasks.py`及冻结`data/evidence/store.json`，不覆盖原训练数据或`runtime-handoff.json`。

```python
from evidence_store import load_store
from player_comparison import build_player_profile, compare_players, build_story_context

store = load_store()
profile = build_player_profile(store, '1641708', '0022500701')
comparison = compare_players(store, '1642843', '1641708', '0022500701')
story = build_story_context(store, 'flagg', opponent_id='1641708')
```

- `facts`保留完整来源、evidenceId、原值/单位/范围；`sections`按用途给出evidenceId列表。每名主例球员38项来源事实，另有7项公式计算；缺失项和不可计算项明确保留。
- `derived`保存公式、操作数原值及evidenceId。百分比差使用百分点，先算后四舍五入。零分母返回`available:false/value:null`，不返回无穷或填零。
- `comparisons`只比较同指标、同单位、同范围、同来源快照，本次两样例各18项。不同gameId、不同赛季来源不混算；禁止以进攻Leverage减防守Leverage构造对位胜率。
- `opponentChoices`依据该场官方出场记录，拒绝未出场、同队或不在该场的对象；未确认场上/防守身份保留false。
- 输出`trainedModelUsed:false`，表明这是确定性官方数据与算术。后端建议放入独立`analysis.playerComparison`，与真实RL选择结果分别保留来源。页面“RL选证”标记仍依赖真实模型调用，不能凭这个数据包开启。
- 当前只注册两样片事件；18:00正式素材先补真实映射和官方数据，不能拿样例对手或统计值替换。
