# 源码保存与恢复

用户要求源码不能只存在可能销毁的服务器，必须本地存档。当前最新提供的 AGENTS 约束又要求新增开发暂不推送，与此前及时推送指令冲突；已请求澄清、尚未收到新答复，本轮按**只保存本地、未经再次授权不推送**执行。准备工程此前已推送到私有 [Jackey0903/BroadcastCode](https://github.com/Jackey0903/BroadcastCode)，默认 `main`，Portal 绑定不变。

## 每个开发阶段的保存步骤

1. 把源码保存在本地仓库。云端新增或修改的代码也需取回源码并纳入版本控制；CDK、依赖版本、锁定文件、必要配置样例和运行说明一并保存。
2. 完成与改动相称的检查，核对暂存文件不含凭证，提交明确的阶段版本。获得再次推送授权后再同步远端。推送受阻时保留本地提交和存档，明确报告未同步状态，不把尝试推送当成成功。
3. 先执行 `python3 scripts/archive-source.py`。默认存档目录为仓库旁的 `BroadcastCode-backups/`，与工作目录分开保存。

脚本要求工作目录干净，避免遗漏未提交改动；它只创建本地存档，不推送、不部署、不读取 AWS 凭证。每份存档包含：

|文件|保存内容|
|---|---|
|`repository.bundle`|本地 Git 全部引用的提交历史，可离线克隆|
|`source.tar.gz`|当前提交的全部受版本控制文件，含源码、CDK、锁定文件与文档|
|`practice-media.tar`|本地已有的两段原片、媒体信息、26 张关键帧、旧练习成片及有核验记录的新产品成片；仅白名单文件，不上传 GitHub|
|`manifest.json`|提交 ID、分支、北京时间、文件数量、各份存档及媒体文件的 SHA-256 和恢复核验结果|

脚本会核验 bundle、在临时目录克隆并确认提交及文件列表，还会核对源码压缩包的文件列表。另将白名单练习媒体保存到本地素材存档，逐文件校验内容哈希；缺失文件明确写进 manifest，不宣称其已经备份。使用 `--source-only` 可只存档源码与历史。

依赖、其他构建产物、AWS 登录缓存、`.env` 或含密码通知 PDF 不进入存档。公开练习素材的来源见[样片核查](research/公开训练样片核查.md)；正式素材收到后应独立保存，并按其授权范围决定是否上传。GitHub 不保存大视频；本地素材存档也不包含所有 `data/` 或所有服务器输出。

## 从 GitHub 恢复

在新的目录克隆私有仓库后，先读 `README.md` 和 `AI接手说明.md`。安装锁定依赖，恢复所需视频输入，重新配置 SSO；部署前核对目标账号及 `us-east-1`，遵守既有 bootstrap 和权限边界要求。构建与部署步骤见[产品工程](../product/README.md)与[练习工程](../readiness-lab/README.md)。旧 URL、任务 ID 和临时云资源可能失效，源码恢复不代表部署自动恢复。

## 从本地存档恢复

可用 `git clone /存档目录/repository.bundle /新工作目录` 恢复代码和历史；恢复后核对 HEAD 与 `manifest.json` 的 commit 相同。如需继续推送，将 `origin` 改回本项目 GitHub 地址，本地 bundle 地址不能作为 GitHub 推送目标。只需读取源码时，也可在新目录解压 `source.tar.gz`。

执行恢复时先选择新的目录，不覆盖现有工作目录。存档本身不包含登录凭证；新电脑仍需用户重新认证 GitHub 与 AWS。

需要恢复练习输入时，在新工作目录中用 `tar -xf /存档目录/practice-media.tar --strip-components=1 -C /新工作目录` 解包，再对照 manifest 中各媒体 SHA-256；这样可恢复 `upload_inputs.py` 需要的原片、元数据和抽帧，无需依赖旧云桶。部署工具和字体由打包脚本下载并按已有指纹核验；网络或上游文件变化导致指纹不一致时，应保留失败信息并核准来源版本，不能跳过哈希检查。
