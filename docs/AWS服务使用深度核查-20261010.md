# AWS 服务实际使用与深度核查 · 2026-10-10

依据用户提供的评分原文：原生托管方案优先；同一服务按专业性和业务有效性区分深度；机器评分从仓库重跑，人工评分访问CloudFront。以下是工程核查，不是主办方给出的分值或满分认证。以正式主产品 `product/` 和真实运行证据为准，不能拿旧测试目录、资源数量或服务开通列表当完成情况。

## 核查结论

主成片链路实际采用AWS原生托管、无服务器、事件驱动与CDK；不是将整个系统搬到自建EC2。主链为CloudFront → Lambda API → SQS → Lambda Worker → AgentCore Runtime／Bedrock → S3；DynamoDB记录任务和预算，CloudWatch Logs记录运行与失败。

不是所有可用AWS服务都要使用，也不能说现有每项都已深入。深度必须对应真实业务行为与运行证据。FFmpeg属于自打包的开源渲染组件，在托管Lambda中执行；它不等于使用MediaConvert。新增服务应解决当前问题，不为凑服务数增加链路。

## 当天最值得补的使用深度

1. **CloudFront媒体缓存优先**：不可变的job产物配置独立缓存行为，动态API/任务状态/故事清单保留实时策略。Worker上传带immutable，但[发布器目前会改成no-cache/no-store](../product/scripts/publication.py#L397)，需一并校准；变化前后测首载/等待与命中，不能只改配置就宣称流畅。
2. **SageMaker集成要形成实际闭环**：模型/参考表/评测身份确定后，用限定权限的真实调用参与成片，失败有回退；固定实际模型版本与引用。静态Model/Endpoint基础设施需补CDK定义，动态训练作业可由可复现运行脚本发起。未上线之前保持Claude主链可独立出片。
3. **最小运行观测与恢复**：围绕任务失败、死信或积压补少量有用指标/告警，若时间允许做一次受控失败恢复。当前30次预算、并发1和完整来源校验保留；不为服务数量增加Step Functions、ECS、API Gateway等无必要组件。
